# MAIN PROMPT

Read the following project documents before beginning implementation:

- VISION.md
- SPEC.md
- TASKS.md

Your job is to implement the project incrementally, one task at a time.

Do not skip ahead.
Do not introduce unnecessary complexity.
Do not significantly expand project scope without clear justification.

The project intentionally emphasizes:

- simplicity
- restraint
- readability
- maintainability
- calm visual presentation
- restrained contemporary design
- atmospheric but understated interaction

The goal is not to create a trendy or overengineered musician website.
The goal is to create a tasteful and honest public home for a professional musician.

The project should feel more like a handcrafted contemporary arts website than either:

- an old-fashioned static brochure site
- or a flashy modern web application

---

# Workflow Requirements

For each task:

1. Read and understand the relevant portions of:
   - VISION.md
   - SPEC.md
   - TASKS.md

2. Briefly explain:
   - what the current task is
   - what you intend to build
   - how you plan to approach implementation

Keep this explanation concise and concrete.

3. Implement the task completely.

Use real project assets where available.

Prefer explicitly referenced assets over invented placeholders.

When using provided assets:

- preserve their visual character
- avoid aggressive cropping
- support portrait-oriented imagery gracefully

4. After implementation, explain:
   - what was built
   - important architectural or design decisions
   - any notable tradeoffs

5. Explain what should now be visible or functional in the product.

Describe the concrete signs of success the user should observe when running or viewing the site.

6. End every task response with exactly:

"Please ask questions, provide feedback, or say 'OK' and I will proceed with the next task."

---

# Technical Guidance

Prefer:

- semantic HTML
- clean CSS
- lightweight JavaScript
- lightly structured content organization
- straightforward project structure
- minimal dependencies
- durable and understandable architecture

Avoid:

- unnecessary frameworks
- premature abstractions
- excessive animation
- unnecessary state management
- overly clever architecture
- application-style frontend architecture unless clearly justified

Favor durable and understandable code over sophisticated patterns.

Lightweight frontend enhancement is acceptable when it meaningfully improves:

- atmosphere
- readability
- responsiveness
- maintainability

Examples may include:

- subtle motion
- lightweight rendering helpers
- structured content files
- simple reusable UI patterns

---

# Design Guidance

The visual design should feel:

- warm
- restrained
- spacious
- readable
- human
- music-centered
- atmospheric
- contemporary without feeling trendy

Avoid:

- startup aesthetics
- flashy motion
- dense layouts
- highly commercial presentation
- social-media-style clutter
- glossy "tech demo" aesthetics
- over-choreographed motion design

The emotional tone should communicate quiet confidence and artistic authenticity.

Subtle and restrained interaction design is encouraged where appropriate.

Motion and transitions should feel:

- slow
- calm
- spacious
- nearly invisible

rather than dramatic or attention-seeking.

---

# Implementation Philosophy

Build the simplest reasonable solution first.

Prefer incremental refinement over ambitious upfront architecture.

Only add complexity when:

- it clearly improves usability
- it significantly improves maintainability
- or it directly supports the project vision

When uncertain, choose the simpler implementation.

The project should remain:

- lightweight
- fast
- maintainable
- easy to host
- understandable years later

---

# Scope Discipline

Do not introduce:

- backend systems
- databases
- authentication
- CMS infrastructure
- advanced animation systems
- complex build pipelines

unless explicitly requested later.

Static architecture is preferred.

A modest amount of frontend structure or enhancement is acceptable if it clearly supports:

- maintainability
- content organization
- responsive behavior
- restrained modern presentation

The project should remain fundamentally lightweight and static in character.

---

# Output Expectations

When implementing tasks:

- keep explanations concise
- focus on concrete implementation details
- avoid generic motivational language
- avoid repeating the project vision excessively
- maintain a calm and technically grounded tone
- explain visual and interaction decisions concretely
- preserve alignment with the established atmosphere and tone

The implementation should evolve through clear, reviewable increments.
