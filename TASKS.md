# TASKS

The project should be built incrementally in a small number of controlled stages.

Each stage should:

- produce a working version of the site
- allow visual review and feedback
- avoid premature complexity
- prioritize clarity and maintainability

The implementation should remain lightweight throughout the process.

---

# Task 1 — Foundation & Layout

## Goals

Create the foundational website structure, visual language, and lightweight content architecture.

Establish:

- page layout
- typography
- spacing system
- color palette
- responsive behavior
- section organization
- image handling
- basic navigation
- lightweight content organization
- responsive media layout behavior
- subtle interaction and motion patterns

Use real assets where available and tasteful placeholders where necessary.

At minimum, integrate:

- the primary portrait image (`portrait-with-classical-guitar.jpg`)
- representative contextual imagery from the provided image set
- representative sample media
- realistic placeholder performance/event content

Initial implementation should begin exploring contextual image placement using the provided filenames and their implied musical themes.

## Deliverables

A functional and visually cohesive website structure containing:

- Hero section
- About section
- Music/Video section
- Upcoming performances section
- Recent performances section
- Contact section
- basic multi-page or multi-section navigation structure

The site should:

- render cleanly on desktop and mobile
- establish the overall tone and visual feel
- include placeholder media embeds and sample event entries
- feel calm, readable, and polished
- demonstrate restrained contemporary interaction design
- establish the overall atmospheric direction of the site
- demonstrate thoughtful contextual image usage across sections/pages

## Important Constraints

- keep JavaScript lightweight and purposeful
- avoid unnecessary abstractions
- prioritize semantic HTML and clean CSS
- maintain simple project structure
- use restrained and atmospheric motion only where beneficial
- avoid flashy or app-like interaction patterns

---

# Task 2 — Real Content Integration

## Goals

Replace placeholder content with real media and information.

Integrate:

- professional headshot
- performance photography
- contextual/project-oriented imagery
- image selection informed by musical context and tone
- real biography text
- SoundCloud links or embeds
- embedded performance videos
- real performance/event information
- contact information

## Deliverables

A realistic and publicly presentable version of the site.

This stage should refine:

- spacing
- typography
- image cropping/scaling
- embed presentation
- mobile layout details
- overall polish
- atmospheric consistency
- pacing between sections/pages
- subtle motion refinement

## Important Constraints

- maintain restraint and simplicity
- avoid content overload
- prioritize strongest media first
- preserve readability and calm visual pacing
-- maintain a unified artist identity even across varied musical contexts
- avoid generic gallery-style image presentation
- use imagery intentionally and contextually

---

# Task 3 — Deployment & Domain Setup

## Goals

Deploy the site publicly using GitHub Pages.

Connect:

- GitHub repository
- GitHub Pages hosting
- custom GoDaddy domain
- HTTPS support

## Deliverables

A publicly accessible production website.

The deployment process should be:

- simple
- repeatable
- documented
- low maintenance

Document:

- deployment steps
- domain configuration
- DNS settings
- future update workflow

## Optional Stretch Goals

If appropriate and still lightweight:

- investigate public calendar/iCal integration
- add lightweight event-data workflow
- improve maintainability of event updates

These should only be pursued if they do not significantly increase complexity.

---

# General Development Principles

Throughout all tasks:

- favor simplicity over abstraction
- avoid overengineering
- build only what is needed
- preserve clarity of code and structure
- separate content from layout where practical
- favor durable solutions over sophisticated ones
- maintain strong mobile usability
- keep the site fast and lightweight

The project should remain approachable to future maintenance even years later.
